# OpenETQW Compatibility Ledger

> This ledger records deliberate deviations from original (SDK or retail) ETQW 1.5 behavior, serialization semantics, and data handling (CHARTER §7.4).
> Since owner decision D7 (2026-09-22), OpenETQW makes a **clean network break** from retail 1.5, as openQ4 did: it speaks its own versioned protocol, and retail peers cannot connect. On 2026-09-24 the owner deferred retail 1.5 network compatibility, and on 2026-09-25 **dropped** it. OpenETQW does not claim retail network compatibility. Retail 1.5 game data (paks) is required and supported. Rows written before D7 describe "interop risk" and are kept for history; read that column as gameplay or fidelity risk.
> All engine evidence in this ledger comes from one host: macOS arm64, Apple Clang 21, debug builds. Runtime evidence recorded before 2026-09-25 14:49 used the unpatched English DVD data; OpenETQW targets retail 1.5 (row 052). The engine has never been configured or compiled on Linux or Windows; only the game module was also compiled elsewhere, in hosted CI (rows 033 to 035).

## Network directions (after D7)
1. **OpenETQW client ↔ OpenETQW server (dedicated/listen)**: the goal (M3). Tested so far on one Mac over loopback: a dedicated server with headless clients or the Vulkan client, and a listen server hosted by the Vulkan client with a headless peer (2026-09-25).
2. **OpenETQW clients on different OSes ↔ OpenETQW server**: goal (M3), untested
3. **Retail 1.5 client or server ↔ OpenETQW**: not supported (D7; dropped 2026-09-25). A connect announcing a retail protocol is refused with "Server uses protocol 20293.5" (tested with a raw UDP peer, not a retail client; row 036).
