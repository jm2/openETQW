# M5 plan: high-refresh multiplayer

This is the order of work for charter milestone M5, based on the trace in [`frame-path.md`](frame-path.md). Each step is one reviewable PR, or a game/engine pair, with a test that can fail. The owner decided D1–D10 on 2026-09-25; each **decision** below records the answer. Where the owner asked to match retail 1.5 (D2, D4), the facts come from the retail 1.5 Mac game module (`game001.pk4` of the official Linux 1.5 client installer; it keeps its symbols), with addresses. Written 2026-09-25; revise it as steps land.

M5 is done when:
- replaying one command stream at caps 60/120/144/240 gives the same authoritative state per tick;
- clients at mixed caps show smooth motion;
- captured frame data shows the camera, the viewmodel and remote entities changing every rendered frame, on foot and in one vehicle seat (the seat view is an OpenETQW extension: retail 1.5 draws every vehicle seat at the tick rate; see D2 and D10);
- the listen host is covered;
- changing the cap during play works.

**State (2026-10-18).**
- **Done:**
  - steps 1, 2, 3, 5, 5a, 6–13, 14a and 15–18 (step 3's seat part since 2026-10-19).
- **Step 14:**
  - Built: the seat presentation for the `standard`, chase, `pivot`/`freepivot` (joint blending) and jetpack views.
  - Late look: built for `standard`, chase, rate-limited, `pivot` and `freepivot` seats and the damped first-person `clampDamped*` view (on valley, the husky driver; since 2026-10-20, ledger 064).

2. **Frame timing (engine).** Done (2026-09-25):
   - `com_frameTicks` counts the ticks run in each host frame (single player, network client, server).

   - `high-refresh-determinism` measures the rate during play from the median frame interval, per cap, with an uncapped run for this host's ceiling (also compared tick by tick). Per D1, a cap the host sets (above 0.9 × its ceiling) is reported against min(cap, ceiling), not failed, as frame-poses A1 reports its lowest phase against min(cap, ceiling) (done 2026-09-30).
   - It also fixed the pacer, which ran a 60 cap at 58–59 fps because macOS wakes sleeps about 2 ms late.
   - **Decision D1** (decided 2026-09-25): when the host cannot reach a cap (the macOS host tops out at about 120 fps in a window, the display's rate), the test reports it and does not fail. The owner: high-refresh testing is needed only as far as "the engine is configured to support it and doesn't regress"; no high-refresh hardware goes into testing. openQ4 does the same: its CI never measures the frame rate. So the tests keep the checks that need no fast display (the replay and pose comparisons across caps, the cap never exceeded by more than 3%, the pacer holding a cap well below the host's ceiling to 98%, each schedule reporting its own cap) and only report whether a cap was reached (the former 0.9 × min(cap, ceiling) bound and frame-poses A1's 0.85 × ceiling bound are reports since 2026-09-30).
     - **The same rule for A2 and A8 (2026-10-04, agreed across the macOS, Linux and Windows arm64 runs).** When a cap is above 0.9 × the client's measured ceiling, so that the host sets the rate, the per-frame checks are split.
       - Reported, not failed: A2's count of game-time steps other than one tick, and A8's wall-clock fraction timing.
       - Judged at every cap: A2's game-time ratio, and A8's structural parts (every draw within a tick unlocked, no fraction stepping back, repeats within the allowance, at least one fraction checked).
       - Why: on Windows arm64, with two Vulkan clients sharing one Adreno GPU (ceilings 39.5–75.6 fps), `mixed-caps` missed A2 by 1–35 steps and A8 by up to 13.4 ms, only at such caps.
       - The trade-off: a host never judges those two parts at a cap it cannot reach. The macOS host (ceiling ~120) may report them at caps above 0.9 × the measured ceiling (120, 144 and 240; in `mixed-caps`, whose ceiling is measured while the other client draws, possibly 90 too), and only where they would have failed. the Linux x64 host (~372) and the Windows x64 host (~305) judge them at every cap, A8's 8 ms bound at 240 included.
       - The pass lines of `frame-poses` and `mixed-caps` name each host-limited item, A1's included.
