### openETQW 0.1.0

The first release of openETQW, a native engine for *Enemy Territory: QUAKE Wars* 1.5.
It is an early preview: the game runs, the stock maps load and multiplayer works between
openETQW players, but much is unfinished. Please report problems as GitHub issues.

**You need your own copy of the game.** openETQW contains no game data. It runs the
retail 1.5 data (the boxed DVD with the 1.5 patch, or Steam) and checks at start-up that
the official 1.5 paks are present and unmodified.

### Downloads

| Platform | Packages |
|---|---|
| Windows 11 x64 and arm64 | installer (`-setup.exe`) or zip |
| Linux x64 and arm64 | AppImage, or tar.xz (with a separate debug-symbols tar.xz) |
| macOS 11 or later, Apple silicon (Vulkan needs macOS 26) | the `openETQW.app` |

Each package carries the engine, the game module, the shader compiler and the libraries
your system may lack. `openetqw-0.1.0-SHA256SUMS.txt` lists the checksum of every file, and the
`-pdb.zip` files hold the Windows debug symbols. If the macOS
download is the unsigned `.tar.gz`, see the README inside it for how to let macOS open
the app the first time.

### Getting started

- **Windows / Linux:** install or extract the package and start openETQW. It looks for
  the game data in the usual install locations and asks for the folder on the first run
  if it cannot find it (on Linux, through zenity, kdialog or yad if one is installed).
  You can also start it with `+set fs_basepath <your ET:QW folder>`.
- **macOS:** copy the game's `base` folder into `~/Library/Application Support/openETQW`,
  or start `openETQW.app` and pick your ET:QW folder when asked.

Your settings, saves and shader cache are kept per user, separate from a retail install.

### What works

- The client on Vulkan, with OpenGL as a fallback. Vulkan is the preferred renderer;
  the OpenGL path works but is not as complete. On macOS, Vulkan runs on Mesa's
  KosmicKrisp driver, which ships in the app and needs macOS 26. An older macOS should
  start on OpenGL; that hasn't been tested yet.
- All 12 stock maps run on the dedicated server, with the retail bots and navigation;
  the client has been tested on valley, outskirts, ark, canyon and refinery.
- Multiplayer between openETQW players: dedicated and listen servers, campaigns,
  stopwatch and objective matches. Windows, Linux and macOS have played together on a
  LAN; play over the internet has not been tested much yet.
- High-refresh rendering: on foot and in vehicles, the view, weapons, vehicles and other
  players are drawn every frame instead of at the 30 Hz game tick. In vehicles this covers
  every driver, passenger and gunner seat with a first-person, chase or turret view; the
  jetpack still draws at the tick rate (`g_unlock_vehicleSeats` changes the list).
- Anti-aliasing (MSAA) under Vulkan, at 2x to 16x as your GPU allows (up to 4x on Apple
  GPUs); off with ray tracing on. It takes effect when the game next starts.
- A dedicated server for each platform.
- A fresh install starts with retail's default key bindings and a graphics preset chosen
  from your GPU (the high preset on current hardware).
- The settings menu's Low, Normal, High and Autodetect presets set all their graphics
  settings, and they're saved (a few of those settings don't take effect yet; see Known
  limits). When a change needs a restart, the menu restarts the engine and comes back
  at the main menu.

### Known limits

- Game sound is new and not finished (#436): there is no voice chat and no reverb.
  Positional audio, distance falloff, looping, volume and fades are tested in the mixed
  output on Windows x64, Linux x64 and macOS, but nobody has yet listened to them against
  the original, and sound on the arm64 builds is untested.
- openETQW does not talk to retail 1.5 clients or servers: its network protocol is its
  own, so retail players and openETQW players cannot join each other.
- Bots move around and fight but do not play objectives.
- Under OpenGL some effects are missing, among them the vision enhancer's view; use
  Vulkan where you can.
- The grass cache setting (`r_stuffCacheMegs`) does nothing yet, so Low and Normal
  don't reduce grass and rubbish. Model level of detail does nothing either, as in
  retail 1.5, whose stock models have no detail levels. A changed anti-aliasing setting
  applies only at the next start.
- Maps from addon packs that need the engine to reload aren't supported yet.
- A fresh profile starts as "Player" without retail's login dialog; rename yourself in
  the in-game menus.
